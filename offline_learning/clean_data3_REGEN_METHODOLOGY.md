# clean_data3 — REGENERATING a trajectory (for Tier-1 games)

Read `clean_data3_METHODOLOGY.md` first (slicing recipe, objectives, verify_pool). This file
adds the part for games whose ORIGINAL rollout never produced the states a dynamic needs, so
re-slicing can't fix them — the trajectory itself must be regenerated by driving the real SEXP.

## The tool: autumn_drive.py (drives the real Autumn SEXP, writes a trajectory.csv)

```
cd /home/ays57/bai
uv run python offline_learning/autumn_drive.py <ENV_NAME> <OUTDIR> --actions "<csv>" [--seed 0]
```
- `<ENV_NAME>` = uppercase game code (e.g. `7XF97`, `S2KT7`). `<OUTDIR>` gets `episode_0/trajectory.csv`.
- `--actions` is comma-separated. Clicks are **row-major**: write `click_ROW_COL` (e.g. `click_5_3`),
  which the env emits as `click ROW COL`. Movement/`noop` written verbatim (`left,right,up,down,noop`).
- It **prints an ASCII grid per step** (with a color legend) — read this to see what the game does
  and refine the action sequence. Use seed 0 (default) so train stays consistent with the held-out test.
- Iterate to /tmp first; only write under clean_data3 once the trajectory is clean.

ASCII legend: `.`=black `B`=blue `l`=lightblue `R`=red `O`=orange `g`=green `G`=darkgreen
`y`=gray `W`=white `Y`=yellow `P`=purple `b`=darkblue `?`=unknown.

## Hard-won lessons (from regenerating bt3gb)

1. **Passive/clock dynamics need SETTLE TIME.** A droplet/bullet/object moves 1 cell/tick; to show
   it fall, stack, despawn, or a meter cross a threshold you must insert ENOUGH `noop`s for the
   effect to fully play out before the next action. (bt3gb ice took ~14 noops to settle into a column.)
2. **Author the rare state deliberately.** Drive the agent INTO the exact configuration the gap needs
   (an object at a wall/edge, two objects about to collide, a second click on an occupied cell, a
   stack building in one column). Don't hope it happens.
3. **Avoid spawn overlap** when a game spawns at a fixed cell: leave ≥1 tick between spawns or the new
   object renders on top of the old and they read as one.
4. **Randomize action timing** if the original had a rigid cadence (e.g. action every 4th step) — an
   irregular gap pattern kills any `step % k` shortcut the optimizer could exploit (this is the WHOLE
   point for va6fq).
5. **Keep each dynamic legible.** Prefer doing one thing at a time in a clear region so the slice that
   targets it is clean (one column for a stack, an otherwise-quiet frame for a collision).
6. The regenerated trajectory should cover **ALL** the game's core dynamics (so the curated train is
   self-contained from it), with special care for the gap that motivated regeneration.

## Workflow per game

1. Read `clean_data2/<game>/dynamics.txt` AND the SEXP
   (`MARAProtocol/python_examples/autumnbench/example_benchmark/programs/<ENV_NAME>.sexp`) to fully
   understand every rule and the exact trigger conditions for the gap dynamic(s).
2. Draft an action sequence that walks through every core dynamic, explicitly entering the rare
   state(s). Run autumn_drive.py to /tmp, READ the ASCII frames, and refine until every dynamic
   (especially the gap) is clearly demonstrated with enough settle time.
3. Save the final full trajectory to `clean_data3/<game>/train_regen/episode_0/trajectory.csv`
   (re-run autumn_drive with `<OUTDIR> = .../clean_data3/<game>/train_regen`).
4. Build a filmstrip to eyeball it:
   `uv run python offline_learning/build_dataset_viz.py clean_data3/<game>/train_regen --out clean_data3/<game>/train_regen/viz.html`
5. **Curate** `clean_data3/<game>/train/episode_*` as short contiguous slices OF train_regen
   (verbatim rows, one episode per slice), ~18-22 scored targets, covering every core dynamic
   under BOTH ID and FD, contrastively (positives + near-miss negatives). Same slicing rules as the
   base methodology. Inspect transitions with:
   `import clean_data3_tools as T; T.dump_transitions('<game>','<wl>', data_root='clean_data3')`
   (after train_regen exists, dump_transitions on data_root='clean_data3' reads train/, so dump the
   train_regen file directly by adapting the helper, or just read the CSV.)
6. **Verify**: `T.verify_pool('offline_learning/clean_data3/<game>/train','<wl>')` — confirm the
   gap dynamic is now a SCORED target (not just window context), and the pool is what you intend.
7. Copy `dynamics.txt` verbatim into `clean_data3/<game>/` if not already there; leave `test/` as the
   original verbatim copy (note in COVERAGE that test still lacks the regenerated states).
8. Write/append `COVERAGE.md`: the core dynamics, the gap that required regeneration, the action
   sequence rationale, and the final pool composition (n, by-action, dynamics covered + contrastive
   negatives + which slice shows the gap dynamic).

## Reference: bt3gb is a finished worked example

`train/` (20 curated slices incl. the ice-stack landing slice `[45,46,47,48]`), and a COVERAGE.md
"REGENERATED" section. Inspect it as a template before starting.
