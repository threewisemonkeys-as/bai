- **Order of operations**: Each step, auto-updates (row+1, red-1, bluePhaseFlip) are applied first, then the action’s effects are applied.
- **auto: row+1**: Agent’s row increases by 1. If the new row would be 16 (agent was at row 15), the agent wraps to (1, 2) (column becomes 2 regardless of previous column). The `atBottom` flag is `true` iff the agent’s row is 15 **before** auto-updates for the current step; after wrap, `atBottom` becomes `false`. If no agent exists, this does nothing.
- **auto: red-1**: Every step, each red object’s row decreases by 1. If the new row would be < 0, that red object is removed. This applies to all red objects that exist at the start of the step (before auto-updates). Red objects created during the action phase (e.g., by `up` converting gray) are **not** decremented that step.
- **auto: bluePhaseFlip**: Blue phase toggles (0↔1) whenever the agent’s row **after** applying auto row+1 (and possible wrap) is congruent to 3 modulo 5 (i.e., new row ∈ {3, 8, 13}). This check uses the row value immediately after the row+1 update, before the action is executed.
- **action: left/right**: Only affects the gray object: left decreases its column by 1, right increases its column by 1. No other changes. If gray is absent, left/right have no effect.
- **action: up**:
  - If **no agent exists**: creates an agent at (1, 2). Additionally, if gray exists at any location, that gray is converted to red at the same cell (gray disappears, red appears at that cell; this new red does **not** undergo red-1 this step).
  - If an agent exists and its current row (before auto-updates) is **not** 15: behaves like noop (only auto updates apply), but *if gray exists at any location*, converts that gray to red at its current cell (same conversion rule, no red-1 this step).
  - If an agent exists and its current row is 15: the agent wraps to (1, 2) (after auto row+1 would have wrapped it anyway). Additionally, if gray exists at any location, converts that gray to red at its current cell (again, no red-1 this step).
  - Note: The conversion of gray to red happens during the action phase; the new red’s row is whatever gray’s row was (not decremented this step).
- **action: noop**: Only auto updates apply; no additional effects.
- **Inverse reasoning**: When multiple distinct actions produce the same next state from a given current state, list **all** possible actions that could have caused the transition. Do not select one based on patterns or context. Specific cases:
  - If **no gray object exists**, then actions `left`, `right`, `up`, and `noop` all produce the same next state (only auto-updates apply). This holds regardless of agent row (including row 15, because auto-wrap makes `up` identical to `noop`).
  - If **gray exists** and agent row is **not** 15, then `left`/`right` shift gray, `up` converts gray to red, and `noop` leaves gray unchanged – each action produces a distinct next state.
  - If **gray exists** and agent row **is** 15, then `up` wraps agent and converts gray; `noop` wraps agent automatically but leaves gray unchanged; `left`/`right` shift gray (no wrap of agent because wrap is auto). Again each action has a unique outcome.
- **Feature formatting**: When an object (agent, gray, red) is absent, represent it as `none` (lowercase). For multiple red objects, list them sequentially (e.g., `red:(3,8),(15,6)`). The `atBottom` flag is `true` iff the agent’s row is 15 **before** auto-updates are applied for the current step.
