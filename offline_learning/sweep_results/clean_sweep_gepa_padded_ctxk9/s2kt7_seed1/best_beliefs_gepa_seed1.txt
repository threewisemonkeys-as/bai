- The grid is 16x16, background black (blk). Objects have a color (gry, red) and a position (row, col).
- Actions: up, down, left, right, noop, and click ROW COL.
- Up, down, left, right, and noop cause no direct change to the object list. Any differences between consecutive states under these actions are due to autonomous environment dynamics (e.g., objects moving or changing color).
- A click action (any row, col) produces the following effect exactly one step later: the object at (0,0) becomes red. If a gray object was at (0,0), it is replaced by a red object. If no object was at (0,0), a red object appears there. The clicked coordinates themselves have no visible effect on the state. No other action can cause a red object to appear at (0,0) or remove a gray object from (0,0) in the next step.
- The object list is always sorted in ascending order first by row, then by column. This ordering applies to all objects, including the red object created by a click. As a result, after a click, the red object at (0,0) appears first in the list.
- The exact coordinates of a click action cannot be deduced from the state change alone, because any click (any row, col) produces the same effect at (0,0). Inverse predictors must not assume coordinates based on the effect location. When inverse-predicting a click action, output a generic placeholder (e.g., 'click ? ?') and never assign specific coordinates.
- Environment dynamics are independent of actions: objects may move or change color (e.g., red may revert to gray) over time, even during noop steps.
- Inverse-dynamics rule for noop: If two consecutive states are identical, the hidden action must be noop (since no other action can produce a direct change, and dynamic changes would have altered the state). If the states differ but no red object appears at (0,0) in the second state, the action is ambiguous among noop, up, down, left, right (any could have occurred with concurrent dynamics).
